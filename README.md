# QQ空间

让一个固定角色经营自己的 QQ 空间：接收你引用的照片、按日程分享自拍、回复管理员的评论，并把这些经历同步给 LivingMemory。

插件标识：`astrbot_plugin_qzone_life` · 当前版本：`v0.1.1` · [GitHub 仓库](https://github.com/chouoi344/astrbot_plugin_qzone_life)

## 能做什么

- **引用照片发说说**：引用一条含照片的消息，让角色发空间；没提供文案时，按实际照片和当前人设配文后直接发布。也支持当前消息附图，默认最多 9 张。
- **删除指定说说**：用完整说说标识、链接、独有文案或“刚才那条”定位。匹配到多条时返回候选，供你选择。
- **发布后给自己点赞**：手动要求发布、自主自拍发布都会安排自赞。
- **只自动回复管理员**：读取 AstrBot 已有的 `admins_id`，仅回应这些 QQ 账号在角色自己说说下的新评论。其他用户和机器人自己的评论不会触发回复。
- **根据日程自主分享**：从 Life Scheduler 读取当天穿搭和日程，选择活动时段，调用 Gitee AI Image 生成自拍并配文发布。默认每日目标 1—2 条，相邻自主发布至少间隔 3 小时；你主动要求发布的说说不计入这个额度。
- **同步记忆**：发布、管理员留言、角色回复、删除说说都会记录到 LivingMemory。删帖后保留“曾发布、后来删除”的历史，相关评论记忆也会标明帖子已删除。

自主目标不是每天必须完成的次数。日程不存在、没有合适的剩余时段、图片或模型失败时，当天可能少发或不发；不会为了凑数编造日程。

## 安装与准备

需要 **AstrBot 4.26.8 至 5.0 之前的版本**，通过 `aiocqhttp` 连接 QQ / OneBot。可使用 NapCat；连接需要能够读取消息、机器人账号信息和 `user.qzone.qq.com` 的登录凭证。无需把 Cookie 填进本插件配置。

先安装并配置好以下三个插件：

| 插件 | 本插件用途 | 本次对照的源码版本 |
| --- | --- | --- |
| [LivingMemory](https://github.com/lxfight-s-Astrbot-Plugins/astrbot_plugin_livingmemory) | 保存和召回空间经历 | `2.7.1` |
| [Life Scheduler](https://github.com/muyouzhi6/astrbot_plugin_life_scheduler) | 提供今日穿搭和日程 | `v2.8.0` |
| [Gitee AI Image](https://github.com/muyouzhi6/astrbot_plugin_gitee_aiimg) | 按已有角色参考形象生成自拍 | `v5.7.5` |

1. 在 AstrBot 中设置管理员 QQ 号，并为你与机器人的私聊选择固定角色人设。
2. 确认 LivingMemory 已完成初始化，并允许该私聊使用记忆；保持现有共享、隔离设置即可。
3. 确认 Life Scheduler 能提供当天日程。其当前版本按 AstrBot 的全局默认人设生成日程，因此自主发布要求全局默认人设与空间绑定角色一致。QQ空间只读取已有日程，不会在日程缺失时自行要求它生成。
4. 在 Gitee AI Image 中启用自拍，设置角色参考照或形象库，并配置可用的自拍服务商。QQ空间沿用这些设置。
5. 在 AstrBot 插件页使用本仓库地址安装 QQ空间，设置下表中的文本和识图模型。识图模型必须支持图片输入。
6. 由管理员在与角色的 **QQ 私聊** 中发送 `/空间绑定`，然后用 `/空间状态` 查看结果。

绑定会保存机器人 QQ、管理员私聊、当前人设与 LivingMemory 当前记忆范围。一个机器人 QQ 对应一个固定角色；后台自拍使用这份绑定，评论记忆也使用对应说说原来的绑定，不按每个评论者另建记忆范围。

默认开启自主发布与自动回评，完成绑定后开始工作。更换人设、记忆范围或连接账号后，应先查看状态并核对绑定；插件不会悄悄改成全局记忆，也不会迁移已有记忆。

## 使用方式

| 操作 | 示例 |
| --- | --- |
| 绑定角色与空间 | 管理员私聊发送 `/空间绑定` |
| 引用照片，自动配文发布 | 引用照片后发送 `/空间发布` |
| 引用照片，使用指定文案 | 引用照片后发送 `/空间发布 今天的阳光很好` |
| 查看最近说说及标识 | `/空间列表` |
| 删除指定说说 | `/空间删除 说说标识`，也可用 `/空间删除 刚才那条` |
| 查看任务、记忆同步及错误 | `/空间状态` |
| 暂停自主发布与自动回评 | `/空间暂停` |
| 恢复自主发布与自动回评 | `/空间恢复` |
| 查看结果不明的空间操作 | `/空间待核对` |

模型支持工具调用时，也可以引用照片说“把这张照片发到你的空间”，或明确要求删除某条说说。没有明确发布或删除要求时，不应调用相应工具；模型未能正确调用时可使用命令。

`/空间暂停` 保留手动发布能力，已发生事件的记忆补写继续；它不是停用整个插件。默认只有管理员可以执行发布、列表和删除，自动回评始终只针对管理员。

## 配置

**修改插件配置后需要重载插件。** 不确定时保留默认值，先配置模型与角色。

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `auto_publish` | 开启 | 按日程自主生成自拍并发布 |
| `auto_reply` | 开启 | 自动回复管理员的新评论 |
| `admin_commands_only` | 开启 | 发布、查看列表、删除仅管理员可用；关闭会允许其他聊天用户操作角色空间，不会扩大自动回评对象 |
| `daily_min` / `daily_max` | `1` / `2` | 每日自主目标范围，只支持 1—2；手动发布不计入，删除已发说说也不返还额度 |
| `min_gap_minutes` | `180` | 两次自主发布最短间隔，单位分钟 |
| `active_start` / `active_end` | `8` / `23` | 自主发布时段，含开始、不含结束；开始必须早于结束，不支持跨午夜时段 |
| `poll_seconds` | `180` | 检查新评论的间隔，单位秒 |
| `watch_posts` | `20` | 监测最近多少条自己的说说，可设 1—50 |
| `max_replies_per_poll` | `5` | 每轮最多回复多少条管理员评论 |
| `llm_provider_id` | 留空 | 配文、回评等使用的 AstrBot 模型提供商 ID；留空使用对应会话的当前模型 |
| `vision_provider_id` | 留空 | 识图模型提供商 ID；留空使用对应会话的当前模型，**不是自动继承上面单独指定的文本模型** |
| `persona_id` | 留空 | 限定人设 ID；留空时在绑定时固定当前私聊人设 |
| `timezone` | `Asia/Shanghai` | 日程发布时段与每日次数使用的时区，建议与日程插件保持一致 |
| `selfie_timeout` | `300` | 等待自拍生成的秒数 |
| `llm_timeout` | `90` | 等待配文、识图或回评模型的秒数 |
| `request_timeout` | `45` | QQ空间单次网络请求的秒数 |
| `cookie_ttl` | `1800` | 从 QQ 连接重新获取空间登录凭证的间隔，单位秒 |
| `max_images` | `9` | 一次发布允许的图片数，范围 1—9 |

管理员名单直接沿用 AstrBot 的 `admins_id`，本插件没有另一份回复白名单。名单为空或其中没有数字 QQ 号时，不会自动回复任何人。

## 发布成功，但记忆暂时没写进去

空间操作与记忆同步分别记录。空间已经发出而 LivingMemory 暂时不可用时，会保留待同步任务，稍后补写记忆；不会因为补记忆而重新发说说。重启后会继续处理，并先核对该事件是否已有记忆。

记忆保留事实、实际时间、发布文案、图片文字描述以及评论和回复。图片链接本身不等于理解图片。后续是否召回仍由 LivingMemory 的当前范围、检索和记忆生命周期决定，不能保证每轮聊天都会自动带出全部说说。

## 超时或“结果未确定”怎么处理

发布、删除或回复的请求超时，不代表 QQ空间一定没收到。插件会停止自动重发这类操作，避免产生重复说说或回复。

1. 使用 `/空间待核对` 取得 **操作标识**。
2. 打开 QQ空间确认真实结果。
3. 根据结果发送：

```text
/空间核对 操作标识 未成功
/空间核对 操作标识 已成功
/空间核对 操作标识 已成功 真实说说标识
```

发布成功的核对需要最后一项“真实说说标识”，插件会读取目标说说并核对文案。删除或回复成功的核对使用第二种格式。核对成功会恢复记录和记忆同步，不会再次执行该空间动作；核对未成功后可以重新提出请求。

## 当前边界

- 只操作机器人自己的空间，支持图片说说；没有视频发布、好友空间批量点赞等功能。
- 启用前的旧评论不会补回。首次读取既有说说时，时间无法确认的评论只登记为历史；时间明确在启用后的管理员新评论仍会回复并同步记忆。
- 默认只监测最近 20 条说说，由 `watch_posts` 调整。当前未连续翻取所有历史帖子或全部评论页；接口未返回的较深评论、超出监测范围的旧帖评论可能无法发现。
- Gitee 自拍接入使用其内部方法 `_generate_selfie_image_with_meta`；依赖插件升级后若改动该方法，可能需要更新适配。LivingMemory 的引擎接入同样按上表版本核对，升级后的真实环境需要再验证。
- 目前已完成本地测试，包括模拟 QQ 请求、任务恢复及依赖插件交互；**尚未在你的真实 QQ、模型服务和记忆库上完成端到端测试**。上表是源码对照版本，不表示所有版本组合已实机验证。

## 更新与回退

更新前保留当前插件源码、AstrBot 中对应配置及插件数据目录的备份。数据通常位于 AstrBot 的 `data/plugin_data/astrbot_plugin_qzone_life/`，包括任务状态和图片缓存；以实际安装的数据目录为准。

如需回退，先停用插件，再恢复此前保留的源码及与其匹配的配置、数据备份，随后重载并检查 `/空间状态` 和 `/空间待核对`。不要为了重试而删除状态数据库，否则会丢失发布记录和待核对结果。LivingMemory 的真实记忆由它自己管理，本插件回退不会撤销已经写入的空间记忆。
